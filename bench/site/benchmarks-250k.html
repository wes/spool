How fast is Spool with 250,000 emails?

Spool, Apple Mail, MailMate, Thunderbird and Canary on the same Mac, reading the same 250,000-message mailbox — 150,000 of them in the inbox — from the same local server. Every number is measured from the screen: the time from a click or keypress until the pixels stop changing.

How this was measured

  • One mailbox for everyone. A generated mailbox of 250,000 messages (threads, lists, HTML and plain text) served by Dovecot over IMAP on the same Mac, so no client is helped or hurt by a network. Every client synced all of it before anything was measured.
  • Measured from outside. A small tool posts a real mouse or keyboard event and watches the window through ScreenCaptureKit. It knows nothing about the app under test and needs no cooperation from it, which is the only way to put five different apps in one table.
  • "Finished", not "started". Each time is from the event until the window stopped changing. An app that paints a spinner quickly and the message slowly gets the slow number.
  • Medians. 20 runs for each action (10 for scroll, 5 for launch and quit), median reported. Same window size and position for every client.
  • The instrument adds about 28 ms to every time, the same for every app: one or two frames of a 60 Hz display, plus capture. The fastest an action can measure here is around 45 ms.
  • Memory is physical footprint, the number Activity Monitor shows, including the WebKit processes each client renders HTML mail in. Idle CPU is ten seconds of the client doing nothing, straight after the tests above. Apple Mail and Canary were both still working at that point — Apple Mail at a quarter of a core, Canary at more than one and a half — and the numbers say so rather than waiting until they stopped.
  • Search includes typing the query (about 80 ms of it). MailMate searches when Return is pressed, so its time includes the Return. Thunderbird's Quick Filter, its search-as-you-type, looks at sender, recipients and subject by default but not the message body, which is less work than the others do; the rest search the full text.
  • One client at a time. Each was the only mail client running while it was measured, after it had finished checking the server on launch.
  • Each client as it ships, with two exceptions: Canary's Copilot panel was closed and its "Discover" cards dismissed, so its reader had the same room as everyone else's. The server has an empty Drafts folder, as a real account does; without one Canary stops at a dialog asking for it. Thunderbird keeps no offline copy of Junk and Trash by default; the rest of the mailbox it had in full.
  • Launch is warm: the app has run before and macOS has its files cached, as it does for an app you use every day. "Ready" is when the message list stopped changing.

Where Spool does not win: MailMate uses less CPU sitting idle (0.1% of a core to Spool’s 0.6%). At this size Spool finishes every other test first, scrolling included.

Measured October 2026. The harness, the mailbox generator and the raw results are in the Spool repository under bench/; the numbers can be reproduced on any Mac.
