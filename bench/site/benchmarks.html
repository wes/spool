How fast is Spool?

Spool, Apple Mail, MailMate, Thunderbird and Canary on the same Mac, reading the same 50,000-message mailbox from the same local server. Every number is measured from the screen: the time from a click or keypress until the pixels stop changing.

55 msto open a message
61 msto search 50,000 messages
0.28 sfrom launch to a usable inbox
39 sto sync 250,000 messages

Spool 0.1.11, Mac Studio (M1 Ultra), macOS 15.4. Lower is better throughout. Also: the same tests at 250,000 messages.

At 250,000 messages

The same measurements against a mailbox five times the size, with 150,000 messages in the inbox. Opening a message and moving to the next take exactly as long as they do at 50,000. Search, launch and memory grow with the mailbox, but slowly: five times the mail costs a search 70 ms and launch 18 ms.

How this was measured

  • One mailbox for everyone. A generated mailbox of 50,000 messages (threads, lists, HTML and plain text) served by Dovecot over IMAP on the same Mac, so no client is helped or hurt by a network. Every client synced all of it before anything was measured.
  • Measured from outside. A small tool posts a real mouse or keyboard event and watches the window through ScreenCaptureKit. It knows nothing about the app under test and needs no cooperation from it, which is the only way to put five different apps in one table.
  • "Finished", not "started". Each time is from the event until the window stopped changing. An app that paints a spinner quickly and the message slowly gets the slow number.
  • Medians. 20 runs for each action (10 for scroll, 5 for launch and quit), median reported. Same window size and position for every client.
  • The instrument adds about 28 ms to every time, the same for every app: one or two frames of a 60 Hz display, plus capture. The fastest an action can measure here is around 45 ms.
  • Memory is physical footprint, the number Activity Monitor shows, including the WebKit processes each client renders HTML mail in. Idle CPU is ten seconds of the client doing nothing.
  • Search includes typing the query (about 80 ms of it). MailMate searches when Return is pressed, so its time includes the Return. Thunderbird's Quick Filter, its search-as-you-type, looks at sender, recipients and subject by default but not the message body, which is less work than the others do; the rest search the full text.
  • Each client as it ships, with two exceptions: Canary's Copilot panel was closed and its "Discover" cards dismissed, so its reader had the same room as everyone else's. Thunderbird keeps no offline copy of Junk and Trash by default; the other 95% of the mailbox it had in full.
  • Launch is warm: the app has run before and macOS has its files cached, as it does for an app you use every day. "Ready" is when the message list stopped changing.

Where Spool does not win: scrolling finishes about one frame (18 ms) behind Canary and Apple Mail, and MailMate uses less CPU sitting idle. Both are on the list.

Measured October 2026. The harness, the mailbox generator and the raw results are in the Spool repository under bench/; the numbers can be reproduced on any Mac.
